# Local setup and development

## Supported baseline

The user has Gentoo Linux with OpenRC, Plasma Wayland, NVIDIA RTX 4070 SUPER (12GB), i7-14700KF, Python 3.14.10, and an existing `~/Documents/minecraft-discovery` directory. All tools run explicitly in the foreground unless the user asks otherwise. Avoid `sudo`, Portage changes, system services, network or desktop integration.

The Python controller is `mcio_ctrl==1.5.2` talking to an isolated Minecraft Java `1.21.3` Fabric client with the MCio mod. `mcio-data/instances/DemoInstance` and `DemoWorld` must exist before running the scripts.

## Safely attach the existing local folder to the repository

**Use this only in an existing local folder that is not already a Git repository.** It preserves untracked data; do **not** use `git reset --hard` or delete the directory. Make a backup first if it contains irreplaceable work.

```bash
cd ~/Documents/minecraft-discovery
git init -b main
git remote add origin https://github.com/polskiftw/gmaincraft.git
git fetch origin main
git switch -C main --track origin/main
git status --short
```

If the directory already has a `.git` directory, inspect `git remote -v` and `git status` instead of blindly running the above again. The historical root-level scripts may remain on disk and are ignored at their old locations; canonical tracked copies now live in `experiments/`. `mcio-data/`, `.venv/`, `logs/`, and `checkpoints/` are deliberately ignored. The old navigation checkpoint remains at the same root-level path, so orientation can find it.

To pull subsequent GitHub changes:

```bash
cd ~/Documents/minecraft-discovery
git status --short
git pull --ff-only
```

If you have local edits, commit or stash them before pulling; do not run destructive reset commands merely to make `git pull` succeed.

For a fresh separate clone use `git clone https://github.com/polskiftw/gmaincraft.git` and follow the README. A new clone does **not** contain the existing world or learned weights; install MCio and rerun `navigation_learner.py` to create its checkpoint if needed.

## Dependencies

```bash
cd ~/Documents/minecraft-discovery
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 .venv/bin/mcio demo --mcio-dir "$PWD/mcio-data"
```

Do not recreate an already functioning venv or the MCio demo world just to update the Git checkout. The explicit `cbor2>=5.7.1,<6` compatibility pin fixes a reported decoding failure with CBOR 6.x (MCio issue #6). The demo is a preparation step for a fresh install only.

## Experiments

One process at a time because all scripts use MCio's default ZMQ ports. Run from repository root:

```bash
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 .venv/bin/python experiments/random_agent.py
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 .venv/bin/python experiments/benchmark_agent.py --headless
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 .venv/bin/python experiments/persistent_benchmark.py
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 .venv/bin/python experiments/reward_probe.py
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 .venv/bin/python experiments/navigation_learner.py --visible
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 .venv/bin/python experiments/orientation_learner.py --visible
```

`--visible` shows the accelerated Minecraft client; removing it from supported scripts runs headlessly on the NVIDIA graphics path. The small two-episode random baseline always uses a viewer. Scripts intentionally copy `DemoWorld` to differently named disposable worlds and can overwrite **their own** trial saves; don't point them to a real personal world.

The orientation script expects `checkpoints/navigation_policy.npz` generated by the previous navigation learner. It does not fetch checkpoints from Git. The successful 2026-11-02 run also produced local-only `checkpoints/orientation_policy.npz` and `logs/orientation_training.csv`. These are ignored by Git; preserve the trained weights when running new experiments.

## Running via isolated Gentoo Shell MCP (verified 2026-11-02)

The user's installed custom Gentoo Shell MCP server has an isolated Bubblewrap filesystem rooted at `/workspace` (the host's `~/Documents/minecraft-discovery`); `/home` is hidden and the network namespace has **loopback only**. GPU/DRM device nodes and selected read-only NVIDIA/PCI/DRM sysfs mounts are exposed along with **one host Wayland socket**, but not the host home directory or X11 sockets. A private `/etc/hosts` resolves `localhost` to `127.0.0.1`, which MCio's TCP/ZMQ controller requires. The host launcher is installed under `~/Documents/gentoo-shell-mcp/start-isolated.sh`; its local editable copy is `mcio-data/start-isolated.sh`.

Inside the MCP sandbox, use **nested Gamescope + Xwayland + `--visible`**. The ignored `mcio-data/xwayland-sandbox-wrapper.sh` runs `/usr/bin/Xwayland "$@" -ac` for only its **private sandbox X11 socket**, never the host display.

To watch experiments without having your physical mouse control Minecraft's camera, run the project-local helper:

```bash
cd /workspace
tools/run-mcio-viewer.sh .venv/bin/python -B experiments/orientation_learner.py --visible --run-tag viewer_demo --episodes 8 --eval 5
```

Choose a fresh unique `--run-tag` for each disposable run; the helper does not overwrite the successful reference model. It builds `tools/gamescope-no-grab.c` into ignored `mcio-data/gamescope-no-grab.so` on first use, and loads the shim **only into the Gamescope SDL2 backend**, unsetting `LD_PRELOAD` before starting the MCio Python/Java game. The shim rejects `SDL_SetRelativeMouseMode(SDL_TRUE)` and discards physical mouse motion/click/scroll events in `SDL_WaitEvent`. This prevents the normal desktop pointer from steering the nested camera; **MCio's separate agent input protocol remains usable**. The shortcut does not modify Plasma, the host mouse driver, Minecraft itself, or system libraries. The host's real Wayland session is still shared as before.

Quick deterministic regression test (without launching Minecraft):

```bash
tools/test-gamescope-mouse-filter.sh
```

The SDL2 regression passed (mouse suppressed, key/quit events passed) and an actual Minecraft smoke run under the helper received 10/10 MCio action/observation exchanges. **Physical hover behavior still requires a human check** because scripted smoke tests did not move the real pointer. Gamescope still segfaults with exit 139 *after* the Minecraft process finishes, a separate known issue. On systems not using the custom MCP sandbox, keep the normal host-specific display instructions above.

Run only one MCio experiment at a time (action port 4001 and observation port 8001). Full default orientation trial: 300 episodes, 50 held-out cases, 35 decisions/case and 6 ticks/decision. **Rerunning without a tag replaces the original orientation checkpoint, CSV, and disposable `MDL_OrientationLab_v1` world**. For independent seeds, add a unique `--run-tag` together with `--policy-seed`, `--train-seed`, `--eval-seed`, `--extra-seed`, and `--action-seed`; tagged runs use separate world, model and CSV paths and refuse to overwrite existing tags. Example: append `--run-tag rep_d --policy-seed 2721 --train-seed 81006 --eval-seed 60214 --extra-seed 99504 --action-seed 774` to the Python command above. Preserve the three verified checkpoints.

Gamescope's GPU Vulkan initialization and nested Xwayland are functional, and Minecraft/MCio produced real observations and completed the orientation experiment. However, Gamescope still has an **exit-139 (SIGSEGV) after the child exits**; do **not** consider the overall launcher exit code 139 a successful process exit, nor treat it as proof that the Minecraft training failed. Verify printed evaluations, CSV count, and checkpoint integrity individually. Direct MCio `hide_window=True, gpu_lib="nvidia"` failed with GLFW/EGL when run without Gamescope in this sandbox; do not advertise it as working here. No system daemon, privileged host access, or Linux-wide configuration change is needed for these on-demand tests.

## Check syntax and pure-policy unit tests without Minecraft

```bash
cd ~/Documents/minecraft-discovery
.venv/bin/python -m compileall -q experiments src/gmaincraft tests
.venv/bin/python -m unittest discover -s tests -v
```

The unit tests cover numerical feature and learning math. They **do not** verify actual Minecraft runtime, world resets or reward-event integration. CI deliberately installs only NumPy and does not launch/download Minecraft.

## Retaining useful logs

For an orientation run, copy the lines containing `Original (fixed camera)`, `Original (random camera)`, `New BEFORE training`, `New AFTER training`, `New extra unseen cases`, `Learning time`, and any traceback. The full verbose Fabric log is not necessary unless debugging. The local episode CSVs and `.npz` model files are ignored by Git; code commits alone cannot restore the learned weights. On 2026-11-02, the reference and independent `rep_b`/`rep_c` experiments each saved a distinct validated checkpoint and 300-row CSV; preserve all three locally.

## Public repository boundaries

No auth tokens, personal folders, Minecraft profiles, world saves, trained model binaries, game binaries, screenshots containing sensitive information, or large logs should go into this repository unless explicitly considered and approved. Modifying your own Gentoo global environment is not part of normal development.
