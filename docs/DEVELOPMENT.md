# Local setup and development

## Supported baseline

The user has Gentoo Linux with OpenRC, Plasma Wayland, NVIDIA RTX 4070 SUPER (12GB), i7-14700KF, Python 3.14.10, and an existing `~/Documents/minecraft-discovery` directory. All tools run explicitly in the foreground unless the user asks otherwise. Avoid `sudo`, Portage changes, system services, network or desktop integration.

The Python controller is `mcio_ctrl==1.5.2` talking to an isolated Minecraft Java `1.21.3` Fabric client with the MCio mod. `mcio-data/instances/DemoInstance` and `DemoWorld` must exist before running the scripts.

## Safely attach the existing local folder to the repository

**Use this only in an existing local folder that is not already a Git repository.** It preserves untracked data; do **not** use `git reset --hard` or delete the directory. Make a backup first if it contains irreplaceable work.

```bash
cd ~/Documents/minecraft-discovery
git init -b main
git remote add origin https://github.com/polskiftw/gmaincraft.git
git fetch origin main
git switch -C main --track origin/main
git status --short
```

If the directory already has a `.git` directory, inspect `git remote -v` and `git status` instead of blindly running the above again. The historical root-level scripts may remain on disk and are ignored at their old locations; canonical tracked copies now live in `experiments/`. `mcio-data/`, `.venv/`, `logs/`, and `checkpoints/` are deliberately ignored. The old navigation checkpoint remains at the same root-level path, so orientation can find it.

To pull subsequent GitHub changes:

```bash
cd ~/Documents/minecraft-discovery
git status --short
git pull --ff-only
```

If you have local edits, commit or stash them before pulling; do not run destructive reset commands merely to make `git pull` succeed.

For a fresh separate clone use `git clone https://github.com/polskiftw/gmaincraft.git` and follow the README. A new clone does **not** contain the existing world or learned weights; install MCio and rerun `navigation_learner.py` to create its checkpoint if needed.

## Running via isolated Gentoo Shell MCP (verified 2026-11-02)

The custom Gentoo Shell MCP Bubblewrap sandbox is rooted at `/workspace` (the host's `~/Documents/minecraft-discovery`); `/home` remains hidden, but the **host network namespace is now intentionally shared** (internet DNS/HTTPS and repo-scoped Git/SSH access). This also means the sandbox could reach LAN and host-local network services; filesystem restrictions do not create network isolation. GPU/DRM device nodes and selected read-only NVIDIA/PCI/DRM sysfs mounts are exposed along with **one host Wayland socket**, but not the host home directory or X11 sockets. A private `/etc/hosts` resolves `localhost` to `127.0.0.1`, which MCio's TCP/ZMQ controller requires. The host launcher is installed under `~/Documents/gentoo-shell-mcp/start-isolated.sh`; its local editable copy is `mcio-data/start-isolated.sh`.

Inside the MCP sandbox, use **nested Gamescope + Xwayland + `--visible`**. The ignored `mcio-data/xwayland-sandbox-wrapper.sh` runs `/usr/bin/Xwayland "$@" -ac` for only its **private sandbox X11 socket**, never the host display.

To watch experiments without having your physical mouse control Minecraft's camera, run the project-local helper:

```bash
cd /workspace
tools/run-mcio-viewer.sh .venv/bin/python -B experiments/orientation_learner.py --visible --run-tag viewer_demo --episodes 8 --eval 5
```

Choose a fresh unique `--run-tag` for each disposable run; the helper does not overwrite the successful reference model. It builds `tools/gamescope-no-grab.c` into ignored `mcio-data/gamescope-no-grab.so` on first use, and loads the shim **only into the Gamescope SDL2 backend**, unsetting `LD_PRELOAD` before starting the MCio Python/Java game. The shim rejects `SDL_SetRelativeMouseMode(SDL_TRUE)` and discards physical mouse motion/click/scroll events in `SDL_WaitEvent`. This prevents the normal desktop pointer from steering the nested camera; **MCio's separate agent input protocol remains usable**. The shortcut does not modify Plasma, the host mouse driver, Minecraft itself, or system libraries. The host's real Wayland session is still shared as before.

Quick deterministic regression test (without launching Minecraft):

```bash
tools/test-gamescope-mouse-filter.sh
```

The SDL2 regression passed (mouse suppressed, key/quit events passed) and an actual Minecraft smoke run under the helper received 10/10 MCio action/observation exchanges. **Physical hover behavior still requires a human check** because scripted smoke tests did not move the real pointer. Gamescope still segfaults with exit 139 *after* the Minecraft process finishes, a separate known issue. On systems not using the custom MCP sandbox, keep the normal host-specific display instructions above.

Run only one MCio experiment at a time (action port 4001 and observation port 8001). Full default orientation trial: 300 episodes, 50 held-out cases, 35 decisions/case and 6 ticks/decision. **Rerunning without a tag replaces the original orientation checkpoint, CSV, and disposable `MDL_OrientationLab_v1` world**. For independent seeds, add a unique `--run-tag` together with `--policy-seed`, `--train-seed`, `--eval-seed`, `--extra-seed`, and `--action-seed`; tagged runs use separate world, model and CSV paths and refuse to overwrite existing tags. Example: append `--run-tag rep_d --policy-seed 2721 --train-seed 81006 --eval-seed 60214 --extra-seed 99504 --action-seed 774` to the Python command above. Preserve the three verified checkpoints.

Gamescope's GPU Vulkan initialization and nested Xwayland are functional, and Minecraft/MCio produced real observations and completed the orientation experiment. However, Gamescope still has an **exit-139 (SIGSEGV) after the child exits**; do **not** consider the overall launcher exit code 139 a successful process exit, nor treat it as proof that the Minecraft training failed. Verify printed evaluations, CSV count, and checkpoint integrity individually. Direct MCio `hide_window=True, gpu_lib="nvidia"` failed with GLFW/EGL when run without Gamescope in this sandbox; do not advertise it as working here. No system daemon or privileged host access is needed for these on-demand tests. The user intentionally authorized the launcher's network-namespace change; keep filesystem mounts scoped.

## Learned RGB log-aiming experiment (2026-11-02)

This uses **normal `git` from the network-enabled shell**; models, screenshots, logs and save worlds stay ignored/local. Policy actions are Minecraft mouse look and ATTACK; its only observation is a 12-feature handcrafted oak-brown mask of RGB screenshot pixels. The privileged controller supplies angular shaping **as scalar training reward only**, never target coordinates to the policy. A fixed W approach collects the drop after the agent chooses ATTACK. **This is not a general-purpose tree detector**.

Run one independent 500-episode model (choose a **new tag** and independent seeds; existing runs cannot be overwritten):

```bash
cd /workspace
tools/run-mcio-viewer.sh .venv/bin/python -B experiments/log_visual_aim_learner.py --run-tag rgb03 --episodes 500 --eval 14 --decisions 18 --policy-seed 5503 --train-seed 7725 --eval-seed 8816 --visible
```

The checkpoint is `checkpoints/log_aim_policy_<tag>.npz`, training CSV is `logs/log_aim_training_<tag>.csv`, disposable world is `MDL_LogAim_<tag>`. Training's simple geometric success proxy does **not** demonstrate real mining; do not rely on the in-process first evaluation, which previously suffered stale dropped-item contamination.

**Required independent audit:** use a **fresh new world** and separate held-out camera scenarios, and require real observed oak logs. This evaluator clears old item drops at every reset and verifies no log is collected when walking without attacking:

```bash
tools/run-mcio-viewer.sh .venv/bin/python -B experiments/log_visual_aim_evaluator.py --run-tag audit02 --models rgb01 rgb02 --eval-seed 8816 --eval 20 --visible
```

Audited seed 8815 (`MDL_LogAimAudit_clean01`): untrained 0/20, trained rgb01 15/20, trained rgb02 18/20. Evaluation CSV `logs/log_aim_audit_clean01.csv` has 60 rows. Both 5x12 policy weights/checkpoint files were loaded and finite; source and unit tests are in GitHub. **Initial uncleaned 12/14 metrics and rgb02 untrained 11/14 were contaminated; do not reuse them.** The suspected cause was dropped logs persisting after soft-reset. It is now addressed with reset-time `kill @e[type=minecraft:item]` and a no-attack negative control; still use normal Minecraft mechanics for actual acquisition.

Next work is **letting the neural policy decide movement/collection** and replacing the engineered oak-color mask with a learned, robust RGB vision encoder; do not reward camera aesthetics.

## Learned W/A/S/D pickup and integrated actual mined-log audit (2026-11-02)

**Milestone:** two separate random-weights RGB-feature pickup policies trained with **real Minecraft movement + actual inventory pickup**, starting from controller-summoned dropped oak logs. They see 14 hand-engineered pixel features ONLY; the trainer's geometric item position is used to compute scalar reward, never exposed to the neural policy. The fresh dropped-item audit seed 8804: untrained 2/32, random 16/32, fixed-W 21/32, trained p01 **30/32**, trained p02 **24/32**. A preliminary audit was **aborted** after item drift made an exact distance guard unreliable; fixture summons now force zero **initial** velocity (the original p01/p02 training was completed before that fixture correction), previous items are killed between cases, and suspect distant pickups are excluded. Models stay in git-ignored `checkpoints/`.

The **combined** evaluator creates another disposable copied world with a controller-placed *oak-log BLOCK*, loads previously trained `rgb02` aiming, then separately loads a pickup policy. Camera/attack decisions are neural; clicking is held 100 ticks; pickup key decisions are neural (not scripted W). Actual Minecraft mined-log inventory success for two independent held-out angle seeds (24+32 cases): fixed W 49/56, untrained pickup 21/56, p01 43/56, p02 **51/56**. This does not establish superiority over W in the current centered-trunk setup. A no-attack negative control gets zero. No model training in audit.

## Natural survival-world transfer benchmark (2026-11-02)

Use the connected **Gentoo Shell MCP** directly (`/workspace`). Git fetch,
commit and push are available via a repository-scoped deploy SSH key: there is
no need for a GitHub connector while the shell is connected. The `--prepare`
phase uses a Minecraft 1.21.3 server to generate **normal noise terrain**
with distinct fixed seeds; it verifies saved worldgen settings, and edits the
**new benchmark source world only** to set the Minecraft `spawnRadius` gamerule
to `0`, preventing different benchmark modes starting at scattered spawn
positions. The temporary generator server binds to loopback 127.0.0.1;
there is no need to expose the local offline server to LAN. It never modifies your real saves, `DemoWorld` or previously
collected checkpoints.

```bash
cd /workspace

.venv/bin/python experiments/natural_world_benchmark.py --run-tag n01 --world-seeds 314159266,271828183 --max-ticks 1200 --prepare
tools/run-mcio-viewer.sh .venv/bin/python -u -B experiments/natural_world_benchmark.py --run-tag n01 --world-seeds 314159266,271828183 --max-ticks 1200 --visible
```

The full run starts four successive Minecraft instances for each seed and
may exceed the shell tool's 90-second command timeout. For short verification
use one or two `--modes` and a smaller `--max-ticks`, with a unique run tag.
A run tag owns its source worlds, scored copies and local JSONL results;
**never reuse it** for reruns. Generate a new tag and new source worlds.
Your sandbox must use `--visible` and `tools/run-mcio-viewer.sh` due to known
headless EGL failure. Gamescope may return exit 139 after the benchmark
child successfully closes: verify JSONL output, not just wrapper exit status.

`idle`, `random` and `forward_attack` are intentionally weak baselines.
`legacy_probe` loads existing ignored `rgb02` aim and `p02` pickup checkpoints
but retains a fixed 100-tick mining hold and scripted handoff. It is **not**
a trained end-to-end controller. Only normal Minecraft input acts during
scored play; the evaluator privately scores actual natural log/wood inventory.
Policies never receive hidden target positions or world seed. `AgentView` is
RGB-only for now, without a player-location or inventory API. A 100-tick
pilot on seed 314159265 confirmed the end-to-end benchmark executes but
reported 0 logs for all four modes; that **pilot was unpaired** because the
original world used spawnRadius 10. New runs refuse sources without the fixed
spawn gamerule; observed start-position equality was verified on seed 271828183 for idle
and forward+attack (both observed position 0.5,77,0.5 and yaw/pitch 0). Longer
multi-seed comparisons remain open; an automatic mismatch guard now fails
any paired-mode run whose observed starting position/yaw/pitch differs.

Next: use this benchmark as the independent transfer gate on the path to
full-trajectory RL and uninterrupted wood-to-crafting progression. See
